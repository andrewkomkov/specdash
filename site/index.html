The board

Every feature of every project, laid out by the stage its files justify. Each card says why it sits where it does — all 38 tasks ticked, plan.md present, no tasks.md yet — because a placement you cannot explain is a placement you cannot trust.

Two grains

One card per feature when many projects are open. One card per user story when a handful of features would leave the columns nearly empty — each story placed by its own ticked tasks, not its feature’s.

The whole feature, one click away

Movement, not just position

Task completion per commit, read straight out of git log. Nothing is stored. The dashed line is the total, because work being added is half the story and a chart of percentages alone hides it.

Read-only, structurally

The projects you point it at are your real work. SpecDash treats them as someone else’s.

No write path

The code only opens files for reading. No cache file, no lock file, no “fixing” a malformed document.

Enforced by the kernel

Every project is mounted :ro, so a write is refused even if a future line of code asks for one. CI tries it on every build.

Git without locks

A read-only subcommand allow-list with --no-optional-locks. No index.lock appears while you are mid-rebase.

Nothing leaves

No CDN, no font host, no telemetry, no update check. Every asset is inside the image — including this page.

What it does not protect

SpecDash has no authentication.

No login, no token, no per-project permission. Anyone who can reach the port can read every specification under the mounted root. The command above binds to 127.0.0.1 deliberately — if you want it reachable from elsewhere, put something in front that asks who is calling.
